# RDMD：从偏移定位到可验证的最小规划演化

## 要回答的问题

两图之差不能独立决定演化方向，也不能证明因果。通用 AI 可以读取两图并定位源；是否需要专用模型必须通过同输入、同预算的对照来回答。

本版本选择**规划向已验收的成功执行学习**，但执行只提供候选操作，不直接作为整张规划的真值。候选必须通过任务验收和同类输入回放。失败、取消、未验收或声称成功但回放失败的执行都拒绝学习。

优化目标是：在明示的候选操作集合 C 中，找代价最小的补丁 Δ，使旧规划应用 Δ 后通过当前任务及验证任务；未改部分保留。允许空补丁；允许多个修改位置；无法验证时弃权。不是让图相似度超过 0.8，也不是强制只改一处。

## 监督信号如何产生

1. 从任务规范独立计算正确结果。规范指定筛选阈值、去重键、换算系数和聚合目标。
2. 在可执行 DAG 中运行原规划和一次成功执行的工作流。两者的节点 ID、顺序、数值和任务输入随机化。
3. 从两图生成允许的原子操作：改一个参数、增删边、增删节点。每个操作含旧值前置条件及目标值。执行结果、状态、展示文案不属于可复制的规划参数。
4. 按**总代价从小到大**枚举补丁集合：字段 1、边 2、节点 3。先验证完整补丁的 DAG 合法性，再执行任务。一次节点删除不暗中删除边；一次节点对齐不暗中覆盖多个字段。
5. 所有更低代价候选均被否决后，才把首个可行代价称为最小。收集同价可行解，训练用确定性代表，评测接受等价最优解。
6. 用所选补丁触及节点在两图联合依赖关系中的上游前沿作为 `sourceNodeIds`。它是**最小干预位置**，不是被观测数据唯一证明的真实根因。
7. 生成 `adopt / no_change / abstain` 三类监督。失败执行、证据不足、伪成功、旧规划已经有效都进入训练，避免模型只学会“总要改”。

候选超过 12、搜索超过 4096、找不到可验证方案时禁止给出未经证明的最小性证书。当前生成语料最多 5 个候选，均未触顶。补丁原子应用，允许“新增节点 + 两条边 + 删除旁路”这种必须联合生效的操作。

## 第一阶段训练：带补丁的 SFT

底座为独立 Qwen3-8B + 新 QLoRA adapter；不覆盖 V4/V5 定位 adapter。

输入：任务规范、规划图、执行图、执行验收状态、候选操作和两份可见输入/正确结果。

输出：

```json
{"decision":"adopt","direction":"plan_toward_verified_exec","sourceNodeIds":["n123"],"edits":[{"op":"set_param","nodeId":"n123","field":"minimum","before":5,"after":3}]}
```

训练采用 assistant-only token loss，只读 train/development。默认 2 epochs、rank 16、alpha 32、dropout 0.05、学习率 1e-4、有效 batch 16、NF4 双量化、BF16。用 development loss 选 checkpoint，绝不用 holdout 选参。随机种子固定为 20260923。

每条 completion 必须完整放入上下文；真实 tokenizer 检查，禁止截断 JSON。训练器默认 dry-run，必须显式 `--execute-training` 且通过与代码/语料/权重绑定的预检才会加载权重训练。

这一步让模型直接学习“改什么、改成什么、何时不改”，而不是期待定位训练自动产生修复能力。

## 负例与后续偏好训练

同时生成：照搬全部执行差异、缺少必要操作、错误源点、在失败/未验收执行上学习等拒绝样本，验证器逐条证明它们劣于正例。

这些 preference 文件在本轮用于数据审计、后续偏好训练准备；**当前训练器执行的是 SFT，不声称已经实现或完成 DPO/GRPO**。先测 SFT 的修复成功、无效改动和成本后，再决定是否需要偏好优化，避免在奖励定义没验证前堆训练阶段。

## 验证器与模型分工

模型建议补丁；同一个验证器检查候选授权、前置条件、源点与补丁一致性、成功执行证据、补丁后的任务结果。部署时只能使用可取得的可见验收，不得读取隐藏测试集。

离线评测再用未向模型公开的验证世界及独立 transfer 世界检查泛化；transfer 世界**不参与标签求解**。小改动是复杂度约束，不自动等于防过拟合；后者必须靠新输入上的效果证明。

产品侧接入时应在下一轮规划副本中应用补丁，通过验收后才版本化采用，并保留撤销方案。本目录只提供可执行离线接口 `apply_patch/verify_prediction`，没有修改生产规划器或开启产品动作开关。

`policy.py` 是已实现的离线消费者：只读取可见验收，返回真正修改后的 `nextPlan`、旧/新规划哈希及 `rollbackPlan`。它不读取隐藏测试，也不声称已经接通任意下一轮任务的节点身份映射；跨任务应用必须重新对齐角色并检查前置条件，不能把旧 nodeId 原样硬套。

## 明确的支持边界

本次落地的是**可执行表数据工作流**：source、filter、scale、dedup、aggregate、identity 的有向无环图。它能真实计算任务结果、反事实和有限候选最小成本，适合先证明训练机制可行。

它不是任意研究、PPT、写作或多人协作任务的通用验收器；也不把旧 V5 的“注入错误”反向冒充“成功经验”。要覆盖任意 Janus 任务，必须为对应环境提供可重放执行器和独立验收，采集已验收的真实执行与同类回归任务，再使用同一补丁/搜索/训练接口。没有这些输入时应弃权，不可把自然语言相似度伪装成任务收益。

在有限候选和有限验证世界内的最小性可以穷举证明；任意未来任务的成功、真实因果正确性和专用模型优越性，均不能在训练前保证。
